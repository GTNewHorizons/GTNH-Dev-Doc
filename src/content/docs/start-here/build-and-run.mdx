Build the mod and start the game *before* you change any code. If something
breaks later, you'll know it was your change and not your setup.

This page covers mods that use GTNHGradle, GTNH's shared build plugin, such as
[GT5-Unofficial](/GTNH-Dev-Doc/start-here/set-up-your-workspace/#worked-example-gt5-unofficial).
Finish [Set up your workspace](/GTNH-Dev-Doc/start-here/set-up-your-workspace/)
first. For anything else, use the build and check commands from the
repository's README.

Run the commands from the repository folder, the one containing `gradlew`.
On Windows PowerShell, type `.\gradlew.bat` instead of `./gradlew`.

## Build the unchanged project

```sh
./gradlew build
```

It should end with `BUILD SUCCESSFUL`. If you already built during setup and
haven't changed anything since, you can skip ahead to launching the client.

If the build fails, note the command and the first task that failed, then
see [Gradle problems](/GTNH-Dev-Doc/troubleshooting/gradle-problems/).

You can also build, run the client, and run the server from IntelliJ. The
Gradle tool window lists these tasks, and run configurations come from
GTNHGradle's
[IDE integration](https://github.com/GTNewHorizons/GTNHGradle/blob/04d5d0f931b569497b00e493a0c9a9f606bd2f60/src/main/java/com/gtnewhorizons/gtnhgradle/modules/IdeIntegrationModule.java).
Use whichever you prefer. If a task you expect is missing, see
[Work with Gradle tasks](/GTNH-Dev-Doc/build-tools/work-with-gradle-tasks/).

## Launch the development client

```sh
./gradlew runClient
```

Minecraft should start and reach the main menu. Open the mod list and check
that your mod is there. Then create a throwaway world and find the behavior
you plan to change, so you've seen it before your edit. For GT5, check that
GregTech is loaded and that you can enter the world.

Keep in mind that this is not the full GTNH pack. It runs your mod plus the
dependencies its build declares. The Java version the game runs on is also
separate from the one Gradle uses: to test on another Java version, pick the
matching generated run task. See
[Java and runtime selection](/GTNH-Dev-Doc/build-tools/understand-java-and-runtime-selection/)
for details.

If the game crashes or your code doesn't seem to be loaded, see
[Development client and server problems](/GTNH-Dev-Doc/troubleshooting/development-client-and-server-problems/).
Have the launch output and game logs ready.

## Test on a dedicated server

If your change touches server-side logic, networking, or anything the client
and server exchange, also test on a dedicated server. In singleplayer, the
client and server run in the same Java process, which can hide bugs such as
loading a client-only class on the server or values that never reach the
client.

<Steps>

1. Open a second terminal in the same repository folder and start the server:

   ```sh
   ./gradlew runServer
   ```

2. The first time, the server asks two questions
   ([source](https://github.com/GTNewHorizons/RetroFuturaGradle/blob/e3eaceff02413a6a5e8ac23faa604fee6c91b537/plugin/src/main/java/com/gtnewhorizons/retrofuturagradle/minecraft/RunMinecraftTask.java)):
   - **Online mode:** answer `n`. The development client uses a test account
     that can only join an offline-mode server. Only use this server for local
     testing.
   - **EULA:** read the
     [Minecraft End User License Agreement](https://www.minecraft.net/en-us/eula)
     and answer `y` only if you agree.

   Your answers are saved, so you won't be asked again.
3. Wait until the server log shows `Done`. In the development client, go to
   **Multiplayer** and join `127.0.0.1`. If you changed `server-port`, add
   `:PORT` with your port number. Check the behavior you're working on,
   including whether changes on the server show up on the client.
4. When you're finished, type `stop` in the server terminal.

</Steps>

For GT5, you now have a client and a dedicated server running the same code.
Keep this setup: after your change you'll repeat the same steps and compare.
[Testing expectations](/GTNH-Dev-Doc/testing/testing-expectations/) lists
other checks your change may need, such as saving and reloading a world or
running without an optional mod.

## Iterate and test in the full pack

[In-game testing tools](/GTNH-Dev-Doc/testing/in-game-testing-tools-and-tricks/)
shows how to inspect items, recipes, and saved data, and how to attach a
debugger. You can reload some code changes with HotSwap while debugging, but
restart the game for anything that runs at startup, like registering items or
recipes. Always do a final check in a fresh launch.

If your change involves other mods, recipes, pack configuration, or load
order, [test it in the full pack](/GTNH-Dev-Doc/testing/test-a-change-in-the-full-pack/).
Write down the pack and mod versions, what you did, and what happened.

Once your setup works and you know how to check your change, continue to
[Make your first pull request](/GTNH-Dev-Doc/start-here/make-your-first-pull-request/),
or try the optional
[first GT5 change](/GTNH-Dev-Doc/start-here/make-your-first-gt5-change/) for practice.
